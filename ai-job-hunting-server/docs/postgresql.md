# PostgreSQL 使用与验证

## 初始化新数据库

使用 JDK 17 和 PostgreSQL 16 或更新版本。JDBC 驱动固定为 `42.7.10`，继续使用现有 MyBatis-Plus Mapper。以下命令在仓库根目录执行。

先由数据库管理员创建专用用户及 UTF-8 数据库。例如，连接管理库后执行：

```sql
CREATE ROLE ai_job LOGIN;
```

在 `psql` 中用 `\password ai_job` 交互设置密码，随后执行：

```sql
CREATE DATABASE ai_job OWNER ai_job ENCODING 'UTF8' TEMPLATE template0;
```

使用应用用户初始化新库，保证表和自增序列的权限一致：

```bash
psql -h localhost -U ai_job -d ai_job -v ON_ERROR_STOP=1 --single-transaction \
  -f ai-job-hunting-server/src/main/resources/schema.sql
```

`schema.sql` 只创建 8 张业务表及原有索引，不创建数据库，也不删除现有对象。默认使用 `public` schema；如需其他 schema，须让初始化连接的 `search_path` 与应用 JDBC 的 `currentSchema` 一致。脚本应仅对新库执行一次；重复执行会报错并回滚本次初始化。

## 应用连接

默认配置和 `dev` 配置均读取：

| 环境变量 | 含义与默认值 |
| --- | --- |
| `DB_URL` | 必填，例如 `jdbc:postgresql://localhost:5432/ai_job` |
| `DB_USERNAME` | 必填，例如 `ai_job` |
| `DB_PASSWORD` | 必填，通过部署环境提供 |

也可使用 Spring Boot 标准的 `SPRING_DATASOURCE_URL`、`SPRING_DATASOURCE_USERNAME`、`SPRING_DATASOURCE_PASSWORD` 覆盖连接。不要将密码放在 JDBC URL、命令行参数或提交的配置中。Docker Compose 需要显式提供可从容器访问的 `DB_URL`。

仓库配置仅包含环境变量和占位值，启动时还需设置 `SMART_ADMIN_PASSWORD`。`spring.sql.init.mode=never` 禁止启动时自动建表；默认关闭远程清理、支付对账和邮件任务。用户自有模型在插件中配置，生产部署以 [镜像部署说明](docker-image.md) 为准。

## 数据兼容边界

- 原自增主键使用 `bigint GENERATED BY DEFAULT AS IDENTITY`；订单 ID 仍由应用提供。Java `Long` 对应的用户及邀请标识统一使用 `bigint`。
- `is_active` 使用 `boolean`，有效值为 `true`，逻辑删除值为 `false`。AI 配置的 `status`、`test_passed` 保留数字状态。
- `datetime` 转为 `timestamp without time zone`，不引入新的时区换算。迁移时须核对原数据的时区语义，并保持 JVM 时区一致。
- 保留表名 `"order"` 和列名 `"desc"`，手写 SQL 必须使用双引号。JSON 内容继续存放在字符串字段中，金额保持 `decimal(10,4)`。
- PostgreSQL 的普通字符串比较区分大小写；原 MySQL 不区分大小写的比较行为需要在迁移验收时核对，尤其是邀请码和平台标识。

本次代码切换不搬迁已有数据。实际迁移前应备份、暂停写入，将 MySQL `bit` 映射为布尔值，并核对空日期、字符编码、行数、主键和邀请唯一约束。导入显式 ID 后，需对 7 张自增表分别校准序列，再恢复写入；订单表没有自增序列。例如，仅在停写并确认目标库后执行：

```sql
SELECT setval(pg_get_serial_sequence('user_info', 'id'),
              COALESCE(MAX(id), 1), MAX(id) IS NOT NULL)
FROM user_info;
```

## 隔离回归测试

`PostgreSqlPersistenceTest` 直接加载生产 DDL、Mapper、分页插件和审计填充，不加载应用配置，不调用 AI、邮件或支付服务。每个测试创建随机 schema，并回滚全部 DDL 和测试数据。测试只接受 `127.0.0.1` 上名为 `ai_job_test` 的专用数据库，连接用户固定为 `ai_job_test`；该用户需要创建 schema 的权限。

准备好独立本地实例后，在 `ai-job-hunting-server/` 执行：

```bash
AI_JOB_TEST_JDBC_URL=jdbc:postgresql://127.0.0.1:5432/ai_job_test \
  mvn -Dtest=PostgreSqlPersistenceTest test
mvn -DskipTests package
```

测试密码可通过 `AI_JOB_TEST_DB_PASSWORD` 提供。未设置测试 URL 时该测试类会跳过；不要将跳过当作通过。使用 JDK 17 运行 Maven。现有 `EmailTest`、`JobAgentTest` 等涉及外部服务，完整测试应在相应隔离环境中另行执行。

参考：[PostgreSQL 建表语法](https://www.postgresql.org/docs/16/sql-createtable.html)、[MyBatis-Plus 逻辑删除](https://baomidou.com/guides/logic-delete/)。
